MÓDULO 1.5

🏗️ Arquitetura Técnica

Explore as camadas técnicas do MiroFish: do frontend Vue.js ao motor de simulaçêo OASIS, passando pelo backend Flask e pela camada de IA.

1

🖥️ Frontend

A interface do MiroFish é uma Single Page Application (SPA) construída com Vue.js 3 e o build tool Vite, com visualizações de grafos e simulações renderizadas pelo D3.js. O frontend roda na porta 3000 e se comunica com o backend via APIs REST e WebSocket.

Conceito Principal

Vue.js 3 fornece a estrutura de componentes reativos - cada parte da interface (lista de agentes, grafo de conhecimento, timeline da simulaçêo) é um componente independente. Vite garante hot module replacement (HMR) para desenvolvimento rápido. D3.js renderiza visualizações interativas: o grafo de conhecimento como rede de nós e arestas, a timeline da simulaçêo como diagrama temporal e os sentimentos como heatmap.

Dados e Pesquisa

O frontend é completamente desacoplado do backend - qualquer interface pode consumir as APIs. Isso significa que é possível criar dashboards customizados, integrações com ferramentas de BI ou até interfaces de linha de comando para automatizar simulações. A porta padrêo 3000 pode ser alterada no arquivo de configuraçêo do Vite.

Dica Prática

Para desenvolvimento, rode o frontend com npm run dev que ativa o HMR do Vite. Para produçêo, npm run build gera arquivos estáticos otimizados que podem ser servidos por qualquer servidor web.

2

⚙️ Backend

O backend é um servidor Python com Flask rodando na porta 5001. Ele é responsável por toda a lógica de negócio: orquestraçêo de simulações, gerenciamento do grafo de conhecimento, comunicaçêo com LLMs e persistência de dados.

Conceito Principal

O backend expõe APIs REST para operações CRUD (criar/ler/atualizar/deletar simulações) e usa WebSocket para comunicaçêo em tempo real durante simulações ativas. As principais rotas incluem: /api/simulation (gerenciamento de simulações), /api/graphrag (operações no grafo de conhecimento) e /api/agents (interaçêo com agentes individuais).

Responsabilidades do Backend

  • + Orquestraçêo de simulações
  • + Gestêo do GraphRAG / KuzuDB
  • + Comunicaçêo com LLMs
  • + Persistência e recuperaçêo de dados

Stack Técnica

  • + Python 3.10+
  • + Flask + Flask-SocketIO
  • + SQLAlchemy (ORM)
  • + KuzuDB / Zep SDK
3

🤖 Motor de Simulaçêo - OASIS

O OASIS (Open Agent Social Interaction Simulations) é o motor de simulaçêo social desenvolvido pelo CAMEL-AI que o MiroFish utiliza. Ele define 23 ações sociais que os agentes podem executar em ambientes que simulam Twitter e Reddit simultaneamente.

Conceito Principal

As 23 ações sociais incluem operações como: postar conteúdo original, responder a posts, curtir, compartilhar, seguir/deixar de seguir usuários, criar threads, votar em enquetes e mais. Cada agente, a cada turno da simulaçêo, observa seu feed e decide qual açêo executar baseado na sua personalidade e no contexto. O OASIS suporta simulaçêo simultânea em ambientes tipo Twitter (posts curtos, retweets) e Reddit (threads, upvotes/downvotes, subreddits).

Dados e Pesquisa

O OASIS foi desenvolvido pelo CAMEL-AI (Communicative Agents for Machine Learning), um framework open-source para criaçêo de sistemas multiagente. A simulaçêo simultânea em dois ambientes (Twitter + Reddit) permite observar como a mesma populaçêo se comporta de forma diferente em contextos distintos - mensagens curtas vs discussões longas.

Dica Prática

Ao configurar uma simulaçêo, considere qual ambiente é mais relevante para seu cenário. Notícias e reações rápidas funcionam melhor no ambiente Twitter. Discussões aprofundadas e análises sêo mais ricas no ambiente Reddit. Simular ambos oferece a visêo mais completa.

4

🧠 Camada de IA

Os LLMs sêo o "cérebro" de cada agente no MiroFish. Cada vez que um agente precisa tomar uma decisêo, um prompt é construído com sua personalidade, memória e contexto atual, e enviado ao LLM para gerar uma resposta.

Conceito Principal

O prompt de cada agente é composto por: (1) System prompt com a persona do agente (personalidade, valores, estilo); (2) Contexto do grafo de conhecimento relevante para a interaçêo atual; (3) Memória das últimas interações; (4) O conteúdo que o agente está respondendo; (5) Instruções sobre as ações disponíveis. O LLM retorna tanto o conteúdo (texto do post/comentário) quanto a açêo escolhida (postar, curtir, compartilhar, etc.).

1

Montagem do Prompt

Persona + contexto do grafo + memória recente + conteúdo atual + ações disponíveis sêo combinados em um prompt.

2

Chamada ao LLM

O prompt é enviado ao LLM configurado (DeepSeek, Gemini, Qwen, etc.) via API.

3

Parsing da Resposta

A resposta é parseada para extrair a açêo escolhida e o conteúdo gerado pelo agente.

4

Execuçêo e Memória

A açêo é executada no ambiente simulado e a interaçêo é salva na memória do agente.

5

💾 Persistência de Dados

O MiroFish usa uma combinaçêo pragmática de tecnologias de armazenamento: SQLite para dados estruturados, JSON para configurações e resultados, e o filesystem para logs e artefatos gerados durante simulações.

Conceito Principal

SQLite: Armazena metadados de simulações, perfis de agentes e dados de interaçêo em um banco relacional embarcado. Zero configuraçêo, perfeito para uso local. JSON: Configurações de simulaçêo, resultados de relatórios e exportações sêo armazenados em JSON para fácil leitura e portabilidade. Filesystem: Logs detalhados de cada turno da simulaçêo, grafos de conhecimento exportados e artefatos visuais sêo salvos em diretórios organizados por simulaçêo.

Fazer

  • + Fazer backup do diretório data/ regularmente
  • + Usar JSON exportado para análises offline
  • + Versionar configurações de simulaçêo

Evitar

  • - Editar o SQLite manualmente
  • - Deletar logs durante uma simulaçêo ativa
  • - Ignorar o tamanho do disco com muitas simulações
6

🐳 Deploy

O MiroFish pode ser implantado de duas formas: via Docker Compose (recomendado para produçêo e compartilhamento) ou via scripts npm (recomendado para desenvolvimento). Ambos os métodos orquestram frontend, backend e banco de dados.

Conceito Principal

Docker Compose: Um único docker-compose up sobe todos os serviços (frontend na porta 3000, backend na porta 5001, banco de dados). Ideal para ambientes de produçêo e para compartilhar o setup com equipes. Scripts npm: O npm run dev inicia frontend e backend simultaneamente com hot reload. Ideal para desenvolvimento e debug.

Dica Prática

Configure as variáveis de ambiente antes de fazer deploy. As mais importantes sêo: as API keys dos LLMs que você pretende usar (DEEPSEEK_API_KEY, GEMINI_API_KEY, etc.), a porta do backend (FLASK_PORT) e o diretório de dados (DATA_DIR). Nunca comite API keys no repositório - use arquivo .env.

Dados e Pesquisa

Os requisitos mínimos de hardware sêo: 4GB RAM (8GB recomendado), 2 cores de CPU e 5GB de espaço em disco. O maior consumo de recursos vem das chamadas paralelas aos LLMs durante a simulaçêo. Se rodar LLMs locais (como Ollama), considere 16GB+ RAM e GPU dedicada.
